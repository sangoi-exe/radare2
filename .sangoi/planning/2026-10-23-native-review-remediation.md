For volatile effects, retain the existing CALLOTHER opcode, builtin identity, pointer/value operands, trailing space index, serialized form and presentation. The conditional failure is classification loss: conversion removes the operation from STORE iteration, but alias/heritage/merge and ordinary-load crossing still use that iteration or STORE-only checks. Preserve memory-effect equivalence through a narrow shared interpretation in existing native operation/userop owners and their proven direct consumers, reusing existing guards and overlap calculations. This is not a new effect registry or general memory framework. Exact internal placement follows real-witness evidence before correction dispatch.

Retaining LOAD/STORE instead would change the native operation/encoded contract and would still need a new observability contract: current hold-output preservation and explicit volatile-read handling depend on call classification, while existing normalization can remove memory opcodes. Current evidence does not establish that alternative as necessary or simpler. It is not selected. Clearing only `spacebase_ptr` misses the other proven consumers and is not the selected correction.

The native header/implementation, existing tests, bridge caller and engine pin move together; compiled consumers must be rebuilt. No alias, dual API or persisted-shape change is selected.

The calling-convention correction retains the already distinct source and operational facts.

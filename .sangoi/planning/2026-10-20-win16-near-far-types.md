## Required result and primary behavior

A declaration supplied to the default native host path retains its base type, declarator ordering and explicit near/far distinctions through host storage, bridge import and readable type output. Each pointer layer has its own representation. In the admitted x86/16 target, explicit near and far data pointers occupy two and four bytes respectively. A mixed near-to-far declaration must not become two identical-width pointer layers.

Unqualified declarations use the selected target's default sizes, not the plugin build host's `sizeof` or the width of the synthetic analysis address space. Fundamental widths must agree at the host layout and bridge boundaries. Fixed-width integer names retain their fixed-width meaning. Correcting x86/16 does not make every architecture with a 16-bit instruction mode use the same C data model.

The selected x86/16 analysis model keeps `long long` at eight bytes, matching the established host and bridge behavior. Correct the previously unconsumed native `long_long_size=4` metadata to eight bytes at its canonical patch/specification owner, then consume that value through the native API. This is a correction inside the existing owner chain, not a new compiler-support or ABI inference claim.

Data-pointer representation, function-pointer representation and the function's operational calling convention remain separate concepts. Explicit pointer qualifiers must not silently rewrite a calling convention or invent a runtime segment/selector. The existing native segmented pointer representation is reused.

Output includes both the bridge's C rendering and its existing reverse type conversion used by harvest/writeback. A display-only fix that drops qualifiers when types return to the host does not satisfy the requested end-to-end result.

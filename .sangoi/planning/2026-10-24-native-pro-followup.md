## Selected route and Technical rationale

The demonstrated defect is conflation of two domains. A static NE ordinal is a location identifier, not the selector WORD used by the CPU. The old currentCS write fed an ordinal into ARPL, changing the analyzed segment. A separate direct-FAR path computes j16*0x100000000+imm before ordinary relationship resolution: root reproduced literal selector4 becoming CALL0x400000000 without an independent mapping. Guarding only RuleSegment and SegmentedResolver cannot intercept that constructor path.

The selected route keeps exact runtime fields as ordinary machine-width source-cell/register varnodes and routes both immediate and memory FAR targets through the existing segmented-address operation. Immediate ptr1616/ptr1632 stop manufacturing static C48 control addresses from selector numbers. The pre-flattening decoder association remains useful for relocated operand values; it no longer owns an alternate direct-FAR static-target bypass. Relocated pointer components must preserve their common source fact in both raw and overlay views, rather than treating an original chain placeholder or synthetic overlay WORD as the runtime pointer.

The existing SegmentOp owner resolves relationships on demand through native SSA. Exact heritaged incoming CS relates to the function entry location without assigning numeric CS. A memory input receives a relationship only when the provider justifies that initial source value at the analyzed boundary; function-entry state is not automatically loader-time state. COPY, exact field extraction/reassembly, agreeing merges and transformations proven to preserve descriptor bits15:2 may retain a selector relationship. Writes, free values, unresolved LOAD/INDIRECT, conflicting facts and unrelated arithmetic remain unknown. An intact full pointer, including separately represented components, requires one admitted complete-pointer source fact; adjacency or equal numbers alone is insufficient. Imports prove only a full callable target, not a descriptor relationship from a synthetic group.

The bridge uses canonical host relocation/source/target facts at its existing LoadImage boundary, not another NE parser. Static target resolution remains independent of machine-bit knowledge. Initial-reference facts must be available in the ordinary and partial recovery analyses that consume them. Existing ActionDeindirect consumes proven call coordinates, while existing indirect-jump recovery runs the normal heritage/segment actions before creating edges. No new flow engine, serialized provenance stream, parallel SSA graph, runtime map or whole-program mutation tracker is selected.

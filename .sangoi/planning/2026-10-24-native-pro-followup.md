## Selected route and Technical rationale

### First lot: contextual C48 at Core's existing numeric boundary

The host formatter already splits C48 using the existing segment-granularity context: `0001:05e2` denotes `0x1000005e2`, and `face:89abcdef` retains the entire offset32. The generic numeric parser still reads the same text as Real Mode, with four-character scans and `(selector << 4) + offset`. Root reproduced expression and actual seek returning `0x5f2` for the first token with a real NE loaded. No known-good C48 textual round trip exists; the unchanged formatter and legitimate Real Mode behavior are the comparison anchors.

`libr/util/unum.c` invokes the caller's numeric callback before generic parsing, and `libr/util/math.c` retains the colon token. Core already installs `num_callback` from `libr/core/numvars.inc.c` with its RCore context. NE loading selects `asm.addr.segment.bits=32`; the corresponding typed `RArchConfig.seggrn` also drives formatting. Therefore the selected correction belongs at that existing callback, using the same coordinate context, not in the configuration-free parser or a second address model.

Recognize the existing hexadecimal segmented-token family under C48 context, retain successful function/flag/register lookup precedence, parse both complete bounded components and compose selector16/offset32. Use current scalar/hex conversion primitives and the Core numeric-error path; do not truncate offset32 or fall back to a Real Mode value after claiming an invalid C48 token. The independent segmented-display visibility toggle does not select the coordinate model. No new module, public numeric API, syntax prefix, mode flag, schema or persistence is needed. Other contexts and standalone numeric parsing retain their existing behavior.

The alternative of changing the generic colon parser would change existing configuration-free/rax2 semantics and is not selected. A new textual syntax would propagate a different interface despite an existing contextual boundary and is not selected. The current callback route directly joins existing formatting and expression consumers with less independent machinery.

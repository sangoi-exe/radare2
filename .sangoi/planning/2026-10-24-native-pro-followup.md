## Selected route and Technical rationale

The demonstrated defect is conflation of two domains. A static NE ordinal is a location identifier, not the selector WORD used by the CPU. The old currentCS write fed an ordinal into ARPL, changing the analyzed segment. A separate direct-FAR path computes j16*0x100000000+imm before ordinary relationship resolution: root reproduced literal selector4 becoming CALL0x400000000 without an independent mapping. Guarding only RuleSegment and SegmentedResolver cannot intercept that constructor path.

The selected route keeps exact runtime fields as ordinary machine-width source-cell/register varnodes and routes both immediate and memory FAR targets through the existing segmented-address operation. Immediate ptr1616/ptr1632 stop manufacturing static C48 control addresses from selector numbers. The pre-flattening decoder association remains useful for relocated operand values; it no longer owns an alternate direct-FAR static-target bypass. Relocated pointer components must preserve their common source fact in both raw and overlay views, rather than treating an original chain placeholder or synthetic overlay WORD as the runtime pointer.

The existing SegmentOp owner resolves relationships on demand through native SSA. Exact heritaged incoming CS relates to the function entry location without assigning numeric CS. A memory input receives a relationship only when the provider justifies that initial source value at the analyzed boundary; function-entry state is not automatically loader-time state. COPY, exact field extraction/reassembly, agreeing merges and transformations proven to preserve descriptor bits15:2 may retain a selector relationship. Writes, free values, unresolved LOAD/INDIRECT, conflicting facts and unrelated arithmetic remain unknown. An intact full pointer, including separately represented components, requires one admitted complete-pointer source fact; adjacency or equal numbers alone is insufficient. Imports prove only a full callable target, not a descriptor relationship from a synthetic group.

The bridge uses canonical host relocation/source/target facts at its existing LoadImage boundary, not another NE parser. Static target resolution remains independent of machine-bit knowledge. Initial-reference facts must be available in the ordinary and partial recovery analyses that consume them. Existing ActionDeindirect consumes proven call coordinates, while existing indirect-jump recovery runs the normal heritage/segment actions before creating edges. No new flow engine, serialized provenance stream, parallel SSA graph, runtime map or whole-program mutation tracker is selected.

The two-call diagnostic established a second independent input property: knowing an entry relationship does not prove that the cell survives an intervening call. The first TASM call resolves; the second source pair merges with call-linked INDIRECT values and correctly loses proof. Epoch6 carries a narrowly admitted preservation fact from LoadImage to the existing Heritage::guardCalls boundary. An optional exact-range query, defaulting to no guarantee, states that the storage is independently preserved across otherwise unknown call effects; it supplies no machine bytes or target itself. After the existing call-effect/output classification, only an unknown effect may consume that guarantee instead of manufacturing an uncertain definition. Known writes, killed/return-address effects, explicit STORE handling and the source query's refusal of unresolved INDIRECT remain intact. Main and partial analysis use the same architecture/loader, without a new Varnode flag, duplicated state or clone/serialization path.

The bridge will admit that property only from its current exact relocated-field and fully file-backed, file-declared non-writable NE source classification. Effective IO-map permissions do not establish it. Keep unknown fields excluded from ordinary readonly byte folding; do not infer contents from raw chain placeholders, overlays or captured selectors. This is an explicit static-analysis input contract, not a claim of physical runtime immutability or a globally pure callee. Writable or otherwise unproved storage supplies no guarantee.

Existing alternatives do not provide the complete selected property: readonly routes values through loadFill, while current-function unaffected flags and callee EffectRecord metadata have different owners and meanings. A new Varnode/range flag would add state and clone/codec followers for a fact required only at the existing call boundary. The direct loader query uses that boundary without duplicating target resolution or changing generic storage semantics. The existing precise callee-effect path remains valid when its own independent evidence is supplied; it is not a substitute invented for this fixture.

Protected16 ARPL uses an equivalent low-two-bit replacement with its existing ZF/write behavior, allowing generic mask preservation rather than an ARPL-specific exception. FAR calls save symbolic caller CS before the transfer and restore that value on analyzed normal-return fallthrough. Raw concrete transfer enters the callee before that suffix. This is a normal-return summary, not an extra CPU instruction, a new stack WORD or a rule for JMPF/RETF. Actual Windows observations cover unchanged/changed RPL and a cross-segment normal FAR return; the new native/bridge consumers still require comparison.

Numeric SegmentOp execution and bare machine near/far constants cannot recover a C48 target without a relationship. Explicit analysis coordinates and instruction-derived code locations retain an address-only composition path. Unknown targets stay unresolved rather than acquiring an ordinal. Ordinary Real Mode and other target OS behavior remain outside this correction.

The earlier construction-only path proved source-cell binding, but preserving a raw direct CALL coordinate is not the epoch5 acceptance criterion. The selected unified route removes that separate numeric escape while retaining recoverable proven targets through the shared relationship mechanism. There is no known-good complete selector-separation implementation to restore; prior qualified checkpoints and actual target observations remain comparison anchors.

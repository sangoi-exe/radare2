## Episode F2: stale PPC global-name expectation

The ratio CALL input is double at register4010/f1; actual fixture disassembly includes lfd f1 before CALL100006cc. This is not proof of a missing or incorrectly located floating argument.

Confirmed cause: host set_symbol_flag in libr/core/cbin.c2834–2845 creates automatic global.NAME object flags, and reference analysis in canal.c supplies size-matching scalar storage types. R2Scope.cpp898–903 prefers typed globals; its registerGlobalVar preserves their names. The older fallback assigned a generic one-byte code type, and native PrintC::pushMismatchSymbol prepended an underscore for the wider access. Thus _obj. combines an ordinary obj. flag name with a size-mismatch marker, not a required global namespace. Host8675d018ecb99006d3680a3fcd13949c6a495b5e intentionally added automatic globals after the test/fixture's bridge901c71008b26bcfa51ccab5436c8077435eb9d05 introduction. The fixture and old four-name expectation are unchanged; no old passing execution was established.

Root independently reproduced current C and inspected host/bridge/native ownership. The investigator compared exact fixture, relevant source and runtime linkage, actual graph and symbol geometry. Replacing only the four names in memory makes EXPECT byte-equal to actual output. Selected correction: update those four EXPECT names only; preserve all other bytes and production behavior. Status: selected, not implemented or validated as a test-file correction.
